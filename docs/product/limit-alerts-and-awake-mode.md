# ТЗ: предупреждения о лимитах и режим «Не давать уснуть»

## CAPABILITY

Codex Usage Bar показывает только те периоды лимитов, которые вернул локальный Codex, и позволяет отдельно выбрать порог предупреждения для каждого доступного периода. Пользователь также может временно запретить автоматический сон компьютера, чтобы длительная задача продолжала выполняться без постоянного взаимодействия.

## CONSTRAINTS

- Названия периодов определяются по `windowDurationMins`, а не по названию тарифа.
- Периоды 5 часов, неделя и месяц получают понятные названия; остальные длительности подписываются фактическим количеством часов или дней.
- Если API вернул один период, интерфейс показывает одну карточку, один порог и одно значение в строке меню. Второй лимит не придумывается.
- Если API вернул два периода, для каждого доступен независимый порог предупреждения от 10% до 90%.
- Критический уровень остаётся фиксированным — 10% для любого периода.
- Одно уведомление отправляется при первом пересечении пользовательского порога и ещё одно — при переходе в критическое состояние. Повторное обновление данных не создаёт дубликаты.
- Уведомление содержит название периода, оставшийся процент и локальные дату и время следующего сброса.
- Общий выключатель отключает только уведомления Codex Usage Bar и удаляет уже доставленные уведомления приложения.
- macOS должна явно показывать, когда системное разрешение на уведомления запрещено, давать переход в настройки и кнопку проверки.
- Подложка строки меню рисуется нативным `NSStatusBarButton`, поскольку фон SwiftUI внутри `MenuBarExtra` macOS может игнорировать.
- Панель закрывается при клике вне неё через глобальный монитор мыши; монитор удаляется сразу после закрытия.
- Режим «Не давать Mac уснуть» создаёт системный `PreventUserIdleSystemSleep` assertion и действует до выключения переключателя или закрытия приложения.
- Закрытие крышки MacBook и системная политика крышки Windows не переопределяются. Экран может погаснуть; фоновые вычисления продолжаются, пока компьютер не переведён в сон самой системой.

## IMPLEMENTATION CONTRACT

### Данные

- Вход: `primary`, `secondary`, `usedPercent`, `windowDurationMins`, `resetsAt`, `planType` из `account/rateLimits/read`.
- `planType` используется только как подпись тарифа. Количество и тип периодов определяются фактическим ответом API.
- Порог основного и дополнительного периода сохраняется отдельно.

### Интерфейс macOS

- «Обзор»: карточка каждого доступного периода и чекбокс «Не давать Mac уснуть».
- «Настройки»: общий переключатель уведомлений, отдельный ползунок каждого доступного периода, кнопка тестового уведомления и переход в системные настройки при запрете.
- Пояснение «две батарейки при 10%» удаляется.
- При критическом дополнительном периоде и наличии двух периодов строка меню показывает оба значения. При одном периоде остаётся одно значение.

### Интерфейс Windows

- Меню трея показывает только доступные периоды.
- В подменю порогов присутствует отдельное значение для каждого доступного периода.
- «Не давать компьютеру уснуть» использует системный execution-state и действует только в текущем сеансе приложения.

### Состояния уведомлений

1. `unknown`: разрешение ещё не проверено.
2. `allowed`: тестовые и пороговые уведомления можно доставлять.
3. `denied`: показывается действие для открытия системных настроек.

## NON-GOALS

- Изменение системной реакции на закрытие крышки.
- Обход энергосбережения, разряда батареи или политик администратора.
- Жёсткое предположение, что конкретный тариф всегда имеет строго заданные периоды.
- Собственный сервер уведомлений или хранение токенов аккаунта.

## OPEN QUESTIONS

- Конкретный набор периодов Pro может меняться на стороне Codex. Приложение поэтому следует данным API, а README не обещает фиксированную схему тарифа.
